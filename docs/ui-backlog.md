# UI Backlog（Day 1）

> 本文件依 `UI_Agent_Work_Spec.md` 整理 UI 組的 User Stories、頁面清單與優先順序。
> 路由名稱與模板變數為**暫定值**，需與後端組員確認後更新 `docs/ui-backend-contract.md`。

## 1. 範圍

| 角色 | UI 範圍 |
| --- | --- |
| 學生 | 商品菜單、購物車、結帳／模擬付款結果 |
| 商家 | 商品管理、商家訂單列表 |

後端（Flask 路由、SQLite schema、金額計算、訂單與付款狀態）由後端組員負責，UI 不自行實作商業邏輯。

## 2. 頁面清單

| 頁面 | 模板 | 暫定路由 | 優先順序 | 負責 |
| --- | --- | --- | --- | --- |
| 商品菜單 | `templates/menu.html` | `GET /menu` | 1 | 學生端 UI |
| 商家商品管理 | `templates/merchant.html` | `GET/POST /merchant/products` | 2 | 商家端 UI |
| 購物車 | `templates/cart.html` | `GET /cart` | 3 | 學生端 UI |
| 結帳／建立訂單 | `templates/checkout.html` | `POST /orders/create` | 4 | 學生端 UI |
| 模擬付款結果 | `templates/checkout.html` | `POST /payment/mock` | 5 | 學生端 UI |
| 商家訂單列表 | `templates/orders.html` | `GET /merchant/orders` | 6 | 商家端 UI |

共用版型：`templates/base.html`、`templates/partials/navbar.html`、`static/css/style.css`。

## 3. User Stories 與驗收條件

### US-01 瀏覽商品菜單（學生，優先 1）

**身為**學生，**我想要**看到目前上架的商品與價格，**以便**決定要買什麼。

驗收條件：

- [ ] 商品由後端傳入 `products`，頁面不得寫死正式商品資料。
- [ ] 每張卡片顯示名稱、價格（`NT$`）與圖片或一致的佔位區塊。
- [ ] 商品列表為空時顯示「目前沒有上架商品」。
- [ ] 已下架商品不可加入購物車。

### US-02 加入購物車（學生，優先 1）

**身為**學生，**我想要**選擇數量並加入購物車，**以便**一次選購多樣商品。

驗收條件：

- [ ] 數量不得小於 1。
- [ ] 加入成功顯示「已加入購物車」提示。
- [ ] 加入失敗（商品不存在／已下架）顯示可理解的錯誤訊息。
- [ ] 前端總金額僅供顯示，後端建立訂單時重新計算。

### US-03 檢視與調整購物車（學生，優先 3）

**身為**學生，**我想要**調整數量或移除商品，**以便**確認總金額。

驗收條件：

- [ ] 每筆項目顯示名稱、單價、數量、小計與移除操作。
- [ ] 數量變更後小計與總額更新。
- [ ] 數量至少為 1，移除需使用明確按鈕。
- [ ] 空購物車顯示訊息與返回菜單連結。

### US-04 結帳與模擬付款（學生，優先 4、5）

**身為**學生，**我想要**確認訂單內容並完成模擬付款，**以便**完成點餐流程。

驗收條件：

- [ ] 顯示商品、單價、數量與訂單總金額。
- [ ] 建立訂單與付款為兩個清楚步驟。
- [ ] 付款成功顯示成功訊息與訂單編號（若後端提供）。
- [ ] 失敗時顯示可理解的錯誤訊息。
- [ ] 明確標示「模擬付款／測試流程」。
- [ ] 付款狀態由後端路由更新，不由前端按鈕直接改變。

### US-05 新增商品（商家，優先 2）

**身為**商家，**我想要**新增商品與價格，**以便**讓學生選購。

驗收條件：

- [ ] 表單包含商品名稱、價格與新增按鈕，欄位有可見標籤。
- [ ] 名稱不得空白；價格必須為有效正數（後端仍需驗證）。
- [ ] 新增成功顯示提示並更新商品列表。
- [ ] 後端驗證失敗顯示錯誤訊息。
- [ ] 不自行增加未經確認的修改／下架功能。

### US-06 檢視訂單（商家，優先 6）

**身為**商家，**我想要**查看學生訂單與付款狀態，**以便**掌握出餐與收款。

驗收條件：

- [ ] 訂單由後端傳入，不得寫死資料。
- [ ] 每筆訂單顯示編號、商品與數量、總金額、付款狀態、建立時間。
- [ ] 已付款與未付款以清楚的樣式區分。
- [ ] 沒有訂單時顯示空狀態。
- [ ] 金額直接使用後端資料，不由商家頁面重新計算。

## 4. 待確認事項（需與後端組員 C 確認）

1. 實際路由名稱、HTTP method 與重新導向行為。
2. 商品欄位：`id`、`name`、`price`、`image_url`、`is_available` 是否存在。
3. 購物車儲存方式（session／資料庫）及 `cart_items` 欄位。
4. 訂單與訂單明細的欄位、付款狀態值（`unpaid`／`paid`）。
5. 是否已有 Flash message 與 CSRF 設定；若無，表單如何處理。
6. 金額單位與格式（整數新台幣或含小數）。
